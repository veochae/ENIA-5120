🕵️ The Mission, Continued

In lecture, you learned to spot six kinds of data quality "Gremlins": missing values, duplicates, inconsistent casing, impossible numbers, invalid categories, and timestamps stored as text. Today you audit a real dataset that has all six of them hiding inside it. It's 146 station-year readings from 20 fictional climate monitoring stations.

You are not fixing anything yet. Session 2 is "the surgery," where you learn the tidyverse verbs to actually repair messy data. Today is purely about finding and documenting what's broken, the same way an auditor writes a findings report before anyone touches the books.

🧰 1. The Blueprint: Loading and Inspection

Before you can audit anything, you need the evidence sitting in front of you. read_csv() reads the file off disk and stores it as a table (technically a tibble) in your R Environment.

class() tells you what kind of object something is. glimpse() is a better version of just printing the data. Instead of a wide spreadsheet that runs off the edge of your screen, it turns the table on its side so you can read straight down a list of every column name, its type, and a peek at its first few values.

Analogy: If head() is looking at a table from above, glimpse() is turning that same table 90 degrees so you're reading it like a list instead of squinting across a row.

🔠 2. The Language: Data Type Checks

You already know numeric, character, and logical from Lab 0. This section adds one more layer on top. Within "numeric," there's continuous vs. discrete. Within "categorical," there's nominal vs. ordinal.

  • Continuous: can take any value in between two points. 14.5°C, 14.53°C, and 14.531°C are all valid. Temperature is continuous.
  • Discrete: only takes whole-number counts. You can have 2 extreme weather events or 3, never 2.5. Counts are discrete.
  • Nominal: categories with no ranking. Solar, Wind, and Coal: none of them is "higher" than another.
  • Ordinal: categories with a real order. Low, Medium, High is a ladder. High is genuinely more than Medium.
Analogy: Think of energy_source as hooks on a wall. Solar, Wind, and Coal are just different hooks, none ranked above another. Think of climate_risk_level as rungs on a ladder. Low, Medium, and High are steps, and skipping straight to the top rung means something different than the bottom one.

Why this matters beyond vocabulary: if you ever build a chart or a model using an ordinal variable and R doesn't know it's ordered, R will sort it alphabetically (High, Low, Medium) instead of logically (Low, Medium, High), and your chart will look broken even though nothing crashed.

🔍 3. Forensic Audit: Missingness, Duplicates, Casing

is.na() checks every single cell and returns TRUE if it's missing. colSums() adds up all those TRUEs per column, so you get one number per column instead of thousands of TRUE/FALSE values.

count() groups a column by its distinct values and counts how many rows fall into each one. It's the fastest way to see every version of a label that exists, including the typos and casing mismatches hiding among them.

Careful with duplicates here. Checking duplicated(climate$station_id) by itself will look "duplicated" almost everywhere, because every station legitimately appears once per year. That's 7 rows per station by design, not a Gremlin. A real duplicate in this dataset means the same station AND the same year showing up twice. That's why the worksheet has you count station_id and reading_date together, not station_id alone.

🕵️‍♀️ 4. Logical Detective Work

Remember bracket filtering from Lab 0 Module 5, the pattern vec[vec > 15]? Same idea, now applied to a whole data frame instead of a single vector: df[condition, ] keeps only the rows where condition is TRUE, and drops everything else.

climate[climate$temp_c > 60 | climate$temp_c < -60, ]

The | means OR: a row is kept if temp_c is too high or too low. You'll also use %in%, which checks whether a value is a member of a set, and !, which flips TRUE to FALSE (and vice versa):

climate[!climate$sensor_active %in% c("True", "False"), ]

Read that line right to left. Is sensor_active in the set c("True", "False")? Now flip that (!), and keep only the rows where the answer is FALSE. In other words, keep the rows that don't belong to the valid set.

Why does a whole column turn into text over a few bad values? R has to pick one type for an entire column. If even one row has "Yes" instead of TRUE/FALSE, R can't call the column logical anymore, since logical only allows TRUE/FALSE. So it falls back to character for every single value in that column, clean rows included. One bad label anywhere is enough to break the type for everyone.

🏷️ 5. Flagging with mutate()

mutate() adds a new column to a data frame without changing anything else in it. Today you'll use it to create one new column, has_issue, that's TRUE for any row that failed at least one of your checks above.

Analogy: Think of has_issue as a sticky note you attach to a row. You're not fixing anything, just marking "come back to this one" so next week's cleanup has a starting map instead of starting from scratch.

Combine conditions with | (OR) the same way you did in Section 4. A row gets flagged if any of the conditions is true, not just one specific one.
